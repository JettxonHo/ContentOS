## 1. Canonical Role and Document Boundaries

This file is the **Canonical Decision Register Index** and the unique entry point for ContentOS Decision Records.

The documentation layers have distinct responsibilities:

- This file indexes the canonical Decision set, its evidence, and review-only lifecycle annotations.
- Split Decision files under `docs/decisions/decisions-001.md` through `decisions-024.md` preserve complete or historical Decision records.
- Session files under `docs/sessions/` preserve discussion background, alternatives, confirmation evidence, and historical context.
- Current-truth Specifications preserve the integrated rules that implementation must follow.
- A later Accepted DEC takes precedence when it conflicts with an earlier DEC.
- A lifecycle candidate is a review annotation only and never changes a Decision Status automatically.

Decision summaries, reasons, and impacts below are normalized from the source records for navigation and review. The linked source record remains the detailed historical text.

## 2. Register Rules

- IDs are globally unique and remain immutable.
- Status is copied verbatim when the source explicitly records one.
- DEC-001 through DEC-028 and DEC-030 through DEC-035 are recorded as `Accepted` because their corresponding formalized Sessions contain them in the formal Decisions section. Their split records did not contain an explicit Status field, so that legacy-source limitation remains visible in each row.
- DEC-029 is recorded as `Accepted` on the basis of its active Governance Record. No Source Session was identified.
- Missing Reason or Impact fields are shown as `Not explicitly recorded in the legacy source` and are not invented.
- Candidate lifecycle relationships are review annotations only. They do not change Status and do not mark any DEC as Superseded.
- Later Accepted decisions govern current behavior when an actual conflict exists, per DEC-290, but lifecycle metadata still requires human confirmation.
